# Native CIFAR-10 diffusion

Validated on 2026-10-25, Apple M2 Max, 32 GiB RAM, macOS 27.2,
Go 1.25.3. This is an unconditional 32×32 RGB image generator using
`google/ddpm-cifar10-32`. It does not implement text-to-image or video generation.

The runtime loads the original F32 safetensors checkpoint and runs the UNet and
DDIM sampler in Go. Darwin builds with CGO use the existing Accelerate GEMM;
other builds use Go SIMD kernels. No Python, external inference server, Metal
or Core ML is required at runtime. Python is used only to generate the independent
numerical test reference.

## Checkpoint and reference

- Model revision: `267b167dc01f0e4e61923ea244e8b988f84deb80`.
- Checkpoint: `diffusion_pytorch_model.safetensors`, 143,020,084 bytes.
- Checkpoint SHA-256: `1558dbe3fb093b0857d473e376b711eeda1b186c557be5e85b3a56300cd49f0f`.
- Parameters: 35,746,307 F32 values, 136.36 MiB.
- Reference: PyTorch 2.8.0, Diffusers 0.35.1, safetensors 0.6.2, CPU F32.
- Input: one stored Gaussian sample, generated by PyTorch with seed 42.
- Sampling: DDIM, eta=0, epsilon prediction, leading timestep spacing,
  original linear beta schedule, clipping to [-1,1], final alpha=1.

The same stored initial noise is used on both sides. Go and PyTorch RNG streams
are not assumed to match. The fixture stores reference noise predictions at
three training timesteps and complete sampling results. Seven and 23 steps
exercise inference counts that do not divide the 1,000 training timesteps.

Sources: [model and configuration](https://huggingface.co/google/ddpm-cifar10-32/tree/267b167dc01f0e4e61923ea244e8b988f84deb80),
[UNet2DModel](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/models/unets/unet_2d.py),
[DDIMScheduler](https://github.com/huggingface/diffusers/blob/v0.35.1/src/diffusers/schedulers/scheduling_ddim.py).

## Memory and latency

The fixed graph uses 51.55 MiB of reusable inference buffers, including one
im2col workspace shared by all convolutions. These buffers are scoped to one
generation and reused across its denoising steps. Requests on the same model
are serialized. Weight loading briefly holds both the mapped file and decoded
weights; the mapping is closed before returning the model. Loaded weight data
is 136.36 MiB. These are buffer sizes, not process RSS measurements.

Large group-normalization and SiLU passes now distribute independent groups
across the existing worker pool. Each group's reduction order is unchanged.
The workspace reuses one dispatch task and clears its activation references
after the barrier. Small feature maps stay serial. Steady-state denoising still
allocates zero bytes per step.

Two prebuilt test binaries ran in ABBA ABBA order, with four samples per
version and three timed iterations per sample. Both use `GOMAXPROCS=8`, eight
workers and the same actual checkpoint. Each benchmark warms one UNet step;
model loading and workspace allocation are outside timing. No builds or tests
from this task ran concurrently, but background applications were not paused.

| Measurement | Before | After |
| --- | ---: | ---: |
| Warm UNet step, median | 106.822 ms | 79.043 ms |
| Allocations per warm step | 0 bytes / 0 allocations | 0 bytes / 0 allocations |
| Complete 50-step sampling, median of two CLI runs | 5.180 s | 3.693 s |
| CLI maximum RSS, median | 284.38 MiB | 284.73 MiB |

The warm step takes **26.0% less time**. Separate CLI processes in ABBA order
confirm **28.7% less generation time**, with loading and PNG encoding excluded
from that number. They use seed 42 and 50 steps. All four PNG files have the
same SHA-256:
`8de802b1aa1a6e58343ef2ac621782b2730c7b330510ab1b9fcdc70d8b3a6e82`.

[All warm measurements](m2-max-native-kernels-2026-10-25.csv) and
[all CLI measurements, RSS, page faults and output hashes](m2-max-native-cli-2026-10-25.csv).
The first CLI process had cold executable pages; process wall time and page
fault counts therefore do not establish a paging improvement. No process
reported a swap, which is not a system-wide swap measurement.

The reference binary contains the first native implementation from the
preceding uncommitted working tree; it is not a separate Git revision. Its
SHA-256 is `fa2fdda1f57a9ed263150eb36f2ec6d58dda3d11260eb5dd9fa75a10134dead6`;
the measured final test binary is
`3f1b03d71e97defadbf04596bce8493bfda746aba9e5a0abf723aacbebd3ff5f`.
This comparison isolates scheduling changes within GopherLLM; it does not
compare performance with another inference engine.

## Reproduction

Place `config.json`, `scheduler_config.json` and
`diffusion_pytorch_model.safetensors` from the model revision above in one local
directory. The test does not download weights:

```sh
go build -o /tmp/image-generate ./cmd/image-generate
GOMAXPROCS=8 /usr/bin/time -l /tmp/image-generate -model /path/to/ddpm-cifar10-32 \
  -out /tmp/cifar-seed42.png -seed 42 -steps 50 -threads 8

GOPHERLLM_DIFFUSION_MODEL=/path/to/ddpm-cifar10-32 \
  go test -run '^TestDiffusion' -v .

CGO_ENABLED=0 GOPHERLLM_DIFFUSION_MODEL=/path/to/ddpm-cifar10-32 \
  go test -run '^TestDiffusionCIFARReference$/^noise_' -v .

GOMAXPROCS=8 GOPHERLLM_DIFFUSION_MODEL=/path/to/ddpm-cifar10-32 \
  go test -run '^$' -bench '^BenchmarkDiffusionCIFARStep$' -benchtime=3x -benchmem .
```

Regenerate `testdata/diffusion_cifar10.safetensors` in a separate reference
environment with Python 3.11 or newer and the package versions above:

```sh
python scripts/diffusion-reference.py /path/to/ddpm-cifar10-32 \
  testdata/diffusion_cifar10.safetensors
```

Normal tests also cover rejected graph options, invalid tensor dimensions and
byte ranges, non-finite weights, the training noise schedule, padded convolution,
sample clipping, cancellation and closing. The real-model tests additionally
check seed reproducibility, image dimensions and cancellation during generation.
